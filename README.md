# PubAJ (펍아재)

> 펍아재: 국내 홀덤펍에서 치는 아재들을 낮춰 부르는 말. 이 앱은 그 사람들을 잡으려고 공부하는 앱이다.

홀덤 GTO를 혼자 공부하기 위한 PWA. 프리플랍 차트, 퀴즈, 스팟 계산기, 그리고 Claude API 기반 AI 코치가 들어 있다.

## 기능

| 탭 | 내용 |
|---|---|
| **차트** | 6맥스 100bb 프리플랍 차트 13종 (RFI 5개 + 오픈 대응 8개). 핸드를 누르면 빈도와 AI 해설 |
| **퀴즈** | 프리플랍(차트 기준 채점, 혼합 빈도는 부분 정답) · 팟 오즈/MDF/블러프/아웃츠/EV · 에퀴티 감각(프리플랍·플랍) |
| **계산기** | 내 핸드 + 보드 + 상대 레인지(또는 핸드) + 팟/베팅 → 에퀴티, 필요 에퀴티, 콜 EV, MDF |
| **플레이** | 9인 펍 토너먼트 한 핸드를 리버까지. 결정마다 팟 오즈·추정 레인지 대비 에퀴티·선택지별 EV로 채점, 끝나면 AI 핸드 리뷰 |
| **AI 코치** | 어느 화면에서든 "AI 해설 요청" → 그 스팟 정보를 들고 대화 시작. 이어서 질문 가능 |

### AI 코치 설계

- 숫자는 **앱이 계산**하고(에퀴티·팟 오즈·차트 빈도), AI는 그 숫자를 받아 **쉽게 풀어서 설명**만 한다. 그래서 AI가 숫자를 지어낼 여지가 적다.
- 시스템 프롬프트에 기본 해설집(`src/features/coach/knowledge.md`)이 들어가고, 설정의 "나만의 해설 노트"가 함께 붙는다.
- 해설집 블록은 프롬프트 캐싱으로 재사용되고, 대화 내역은 자동 캐싱된다.
- 기본 모델은 Claude Opus 5.5. 설정에서 Sonnet 5.5 / Haiku 5.5로 바꿀 수 있다. Opus/Sonnet은 서버 측 거절 대체(`fallbacks: "default"`)가 켜져 있다.
- 대화는 스팟마다 따로 저장된다(최근 40개, 브라우저 localStorage).

## 실행

```bash
npm install
npm run dev        # 개발 서버
npm test           # 엔진·차트·퀴즈 테스트
npm run build      # dist/ 에 PWA 빌드
npm run preview    # 빌드 결과 미리보기
```

휴대폰에 설치하려면 `dist/`를 HTTPS 정적 호스팅(GitHub Pages, Vercel, Netlify 등)에 올리고, 브라우저 메뉴에서 "홈 화면에 추가"를 누르면 된다. `base: "./"`라서 하위 경로에 올려도 동작한다.

## AI 코치 연결

설정 탭에서 두 방식 중 하나를 고른다.

### 1. 서버 키 (Vercel) — 기본값
Vercel 함수(`api/anthropic.ts`)가 서버에 등록된 키로 Claude API를 대신 호출한다. 키는 브라우저로 내려가지 않는다.

Vercel → 프로젝트 → Settings → Environment Variables:

| 이름 | 값 | 필수 |
|---|---|---|
| `ANTHROPIC_API_KEY` | Claude API 키 (Sensitive로 저장) | 필수 |
| `APP_PASSCODE` | 접속 비밀번호. 등록하면 앱 설정에 같은 값을 넣은 기기만 쓸 수 있다 | 선택 |

- 환경 변수를 바꾼 뒤에는 **다시 배포**해야 적용된다 (새 커밋 푸시 또는 Deployments → Redeploy).
- `APP_PASSCODE`가 없으면 주소를 아는 누구나 그 키의 크레딧을 쓸 수 있다. 중계 함수는 앱이 쓰는 두 엔드포인트(`v1/messages`, `v1/models/*`)와 앱의 모델 3개만 허용한다.
- 로컬 `npm run dev`에는 이 함수가 없으므로 2번 방식을 쓴다.

### 2. 내 API 키
키를 그 기기의 브라우저에만 저장하고 브라우저에서 Anthropic API로 직접 요청한다(`dangerouslyAllowBrowser`). 혼자 쓰는 용도로만 안전하다.

### 키와 크레딧
- 키는 [Claude Console](https://platform.claude.com/settings/keys)에서 만든다.
- Max/Ultra 요금제의 월 API 크레딧을 쓰려면 claude.ai → 설정 → 결제 → API 크레딧에서 Console 조직을 연결하고, **그 조직에서** 키를 만든다.
- "연결 확인" 버튼은 토큰을 쓰지 않는 모델 조회로 연결을 확인한다.

## 차트 데이터

차트는 세트 → 스택 구간 → 상황 순서로 나뉜다. 차트 탭 맨 위에서 세트를 고른다.

| 세트 | 파일 | 내용 |
|---|---|---|
| 펍 토너먼트 (기본) | `src/data/sets/pub.ts` | 9인, BB 앤티. 딥(100bb+) / 미들(40~80bb) / 숏(15~20bb) / 푸시·폴드(10bb 이하). bk와 Claude의 채팅(2026-10-31)에서 정리한 펍 맞춤 범위 |
| 6맥스 캐시 100bb | `src/data/sets/cash6.ts` | 첫 버전의 학습용 근사 차트 |
| 푸시/폴드 내쉬 | `src/data/sets/nash.ts`, `nashData.ts` | 9인, BB 앤티 1bb, 4~20bb. 앱이 직접 계산한 칩EV 내쉬 균형 (아래) |
| 숏스택 내쉬 | `src/data/sets/shortNash.ts`, `shortNashData.ts` | 9인, BB 앤티 1bb, 10~25bb. 폴드/2bb 오픈/올인 + 리쉬브 + BB 콜까지 계산한 칩EV 균형 (아래) |

**펍 토너먼트와 캐시 차트는 솔버 정확값이 아니다.** 레인지 문자열만 바꾸면 직접 구한 솔버 결과로 교체할 수 있다.

### 푸시/폴드 내쉬 계산

`node scripts/make-nash.mjs`가 `src/data/sets/nashData.ts`를 다시 만든다 (4코어에서 약 5분).

1. 169×169 핸드 클래스끼리의 헤즈업 올인 에퀴티를 몬테카를로로 구한다 (클래스 쌍마다 보드 약 1.2만 개, 시드 고정). 카드 겹침(블로커)도 콤보 수로 반영한다.
2. `src/poker/pushfold.ts`가 가상 플레이(fictitious play)로 균형을 찾는다. 퍼스트 인은 올인 or 폴드, 뒤 자리는 차례로 콜 or 폴드, 콜이 한 명 나오면 나머지는 폴드(오버콜 없음).
3. 모두 같은 스택, 칩EV(ICM 미반영). 결과마다 "어떤 결정을 바꿔서 더 얻을 수 있는 최대치"(exploitability)를 함께 저장하는데 모두 0.02bb/핸드 이하다.

### 숏스택 내쉬 (오픈/리쉬브)

`node scripts/make-shortnash.mjs`가 `src/data/sets/shortNashData.ts`를 다시 만든다 (같은 에퀴티 표 재사용, 4코어에서 약 7분). 모델은 `src/poker/openjam.ts`:

- 퍼스트 인: 폴드 / 2bb 오픈 / 올인. 올인에는 뒤에서 콜 or 폴드 (오버콜 없음).
- 오픈에는 뒤에서 3벳 올인 or 폴드, BB만 플랫 콜도 가능. 리쉬브가 나오면 오픈한 사람이 콜 or 폴드.
- BB가 플랫한 뒤는 체크다운으로 보고, BB가 핸드 종류별로 에퀴티 일부만 가져간다고 가정한다 (`src/poker/realization.ts`: 페어·수티드 브로드웨이·54s+ 커넥터 90%, 수티드 에이스·높은 원갭 85%, 오프수트 브로드웨이 85%, 오프수트 에이스 72%, 약한 오프수트 50%; 스택이 짧을수록 100%에 가깝게, 20bb부터는 그대로). **이 실현율만 판단으로 정한 값**이고 나머지는 계산이다.
- exploitability는 0.07bb/핸드 이하. 10~12bb에서는 거의 모든 자리가 오픈 대신 올인하므로, 레인지 암기 퀴즈는 오픈 빈도가 5% 미만인 자리의 "vs 오픈" 문제를 내지 않는다.

```
"66+, 55:0.75, A2s+, KTo+, AJs-A6s, QJo:0.4"
 77+ = 77~AA   A2s+ = A2s~AKs   22-66, AJs-A6s = 범위   :0.4 = 40% 빈도 (뒤 토큰이 앞을 덮어씀)
```

한 상황에 액션이 여러 개면(예: 작게 열기 → 올인) 위에서부터 채운다. 앞 액션이 100%인 핸드는 뒤 액션에서 빠진다. `src/data/charts.test.ts`가 "뒤 자리가 앞 자리보다 좁지 않은지", "스택이 줄면 올인 범위가 넓어지는지"를 검사한다.

## 솔버 차트 팩

- 우리 솔버(`src/solver/`)로 미리 푼 헤즈업 플랍 전략을 플랍마다 JSON 파일 하나로 `public/packs/`에 둔다 (싱글 레이즈드 팟: BTN vs BB 캐시 100bb·펍 미들 55bb, UTG vs BB 펍 미들 55bb. 트리는 단순화: 플랍 BB 체크/체크레이즈, BTN 33%·75% 벳, 턴·리버 66% 벳). 앱은 필요한 플랍 파일만 받아서 전략·레인지·EV를 보여 준다. 형식은 `docs/solver-packs.md`.
- 시나리오(레인지·팟·벳 사이즈)는 `src/presolve/scenarios.ts`, 플랍 1755종의 우선순위(앞에서부터 잘라도 고르게 퍼진 대표 플랍)는 `src/presolve/flops.ts`.
- `node scripts/presolve.mjs --scenario all --count 100 --budget-minutes 50`: 없는 플랍만 우선순위대로 풀어서 파일과 `manifest.json`을 쓴다. 한 플랍에 코어 1개, 1.3~1.8GB, 약 10분. `--dry-run`은 계획과 메모리 추정만 보여 준다.
- `--shard i/n`: 우선순위 k번째 플랍을 k % n번 샤드에 배정해 그 샤드 몫만 푼다(병렬 작업끼리 겹치지 않음). `--rebuild-manifest`: 아무것도 풀지 않고 디스크에 있는 파일로 `manifest.json`을 다시 쓴다(샤드 결과를 합친 뒤).
- GitHub Action(`.github/workflows/presolve.yml`)이 6시간마다(02:23·08:23·14:23·20:23 KST) 4코어 러너 16개(샤드)로 최대 5시간씩 이어서 풀고, 합치는 작업이 회차마다 `public/packs/`만 한 번 커밋한다(퍼블릭 레포라 무료). 한 회차가 팩 하나(1,755개)를 거의 다 풀고, 남은 플랍이 있으면 끝나면서 다음 회차를 바로 띄워 쉬지 않고 이어 간다(GitHub가 예약 실행을 가끔 건너뛰어서, 6시간 예약은 안전망). 풀 게 없으면 몇 분 만에 끝난다. 수동 실행(workflow_dispatch)에서 시나리오·샤드 수·예산·개수를 바꿀 수 있다.

## 구조

```
src/
  poker/        카드, 레인지 파서, 7장 핸드 평가기, 에퀴티(정확 계산/시뮬레이션), 팟 오즈 계산
  data/         차트 세트 (charts.ts, sets/*.ts)
  features/
    charts/     차트 화면
    quiz/       퀴즈 화면 + 문제 생성기
    calc/       스팟 계산기
    coach/      AI 코치 (프롬프트, 해설집, Claude API 클라이언트, 대화 저장)
    settings/   설정
  play/         핸드 플레이: 9인 베팅 엔진(사이드팟), 봇 규칙, 레인지 추정, 결정 분석
  state/        localStorage 저장소
api/
  anthropic.ts  Vercel 함수: 서버 키로 Claude API 중계
```

핸드 평가기는 테스트에서 단순 무차별 평가기와 무작위 3000판을 비교해 검증한다.

## 핸드 기록

펍에서 친 핸드를 테이블 그림 위에서 기록한다 (`src/features/log/`). 기록은 브라우저 localStorage에만 저장되고, 백업은 JSON 파일 내보내기/불러오기.

1. **테이블**: 2~10인, 내 포지션, 블라인드 레벨, 칩 스택 (자리별 스택, BB 앤티 여부).
2. **핸드**: `AdTd`처럼 문자로 (랭크·수트 키패드, 카드 표도 있음).
3. **액션**: 차례인 자리가 빛나고, 액션한 자리만 누르면 그 사이 자리는 폴드(벳이 없으면 체크). 같은 자리의 두 번째 액션(림프 후 콜 등)도 순서대로 남는다. 금액은 칩으로 넣고 bb·팟·필요 에퀴티가 자동으로 나온다. 엔진(`src/play/engine.ts`)이 차례·콜 금액·사이드 팟을 계산하고, 보드는 스트리트마다 그 장만 문자로 넣는다.
4. **결과**: 쇼다운 상대 핸드를 넣으면 온라인 올인 화면처럼 스트리트마다 각자 승률이 바뀌고(정확 계산, 프리플랍은 몬테카를로), 역전 카드와 아웃이 표시된다. 결과 칩은 엔진이 실제 카드로 정산한다.

`src/features/log/handAnalysis.ts`가 기록을 진짜 카드로 다시 돌리면서, 상대 레인지를 액션마다 핸드 플레이 봇 규칙으로 좁히고(차트에 없는 림프는 넓은 기본 레인지), 내 결정마다 핸드 플레이와 같은 채점(프리플랍은 펍 차트, 플랍부터는 봇 반응 기준 EV)을 붙인다. 같은 핸드는 항상 같은 숫자가 나오도록 핸드별로 시드를 고정한다.

## 핸드 플레이 모드

- 모두 같은 스택(딥 100bb / 미들 55bb / 숏 17bb / 푸시 11bb), BB 앤티 1bb로 시작한다.
- 봇(펍아재)은 프리플랍에서 펍 토너먼트 차트대로, 플랍 이후는 패 강도 규칙(`src/play/policy.ts`)으로 친다. 콜이 많고 블러프가 적은 펍 성향.
- 봇이 액션할 때마다 그 액션이 나올 확률로 1326개 조합의 가중치를 갱신한다. 그래서 상대 레인지 추정은 "이 봇 규칙 기준으로 정확"하다.
- 채점: 프리플랍은 차트 빈도, 플랍 이후는 선택지별 EV(현재 스트리트 기준 근사, 체크는 체크다운 가정, 멀티웨이 벳은 콜러 1명 가정)를 비교한다. **솔버 답이 아니다.**
