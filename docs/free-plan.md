> 상태: **설계 2단계 (무료 버전)**, 2026-11-06. Pro(유료)는 아직 기획하지 않는다. 결제도 붙이지 않는다.
> 앞 단계: [`data-inventory.md`](data-inventory.md) (회원 시스템과 데이터 구분). 서버 구조: [`server-design.md`](server-design.md).

## 2. 무료 버전 구성

비용이 드는 것은 **실시간 AI 대화**와 **기록 동기화(DB)** 둘뿐이다. 나머지는 전부 기기에서 돌아 사용자가 늘어도 우리 비용이 거의 0이다.

| 기능 | 익명 | 가입자 | 우리 비용 | 메모 |
|---|---|---|---|---|
| 퀴즈 (프리플랍, 레인지 암기, 팟 오즈·EV, 에퀴티) | 무제한 | 무제한 | 0 | 기기에서 계산 |
| 차트, 계산기, 핸드 플레이 | 무제한 | 무제한 | 0 | 기기에서 계산 |
| 기록 화면 | 이 기기 기록 (최근 5,000건) | 동기화된 기록 (최근 5,000건) | 0 | 기기 상한 `LIMITS.localAttemptCap` |
| 오늘의 문제 (매일 5문제) | 됨 | 됨 | 0 | 문제 풀은 정적 파일, 고르는 건 기기에서 (server-design 10장) |

## 3. 비용 안전장치 (혼자 운영할 때 필수)

사용자별 한도와 별개로, 전체에 거는 상한이다. 요금 폭탄을 막는 마지막 장치라서 실시간 AI를 여는 날부터 켜 둔다.

- **하루 전체 AI 예산**: 서버가 응답마다 실제 토큰 사용량으로 비용을 더한다. 그날(KST) 합계가 정한 금액을 넘으면 실시간 AI를 모두에게 닫는다.
  - 닫혀 있는 동안 앱에는 "오늘 AI 해설은 마감됐어요. 내일 0시에 다시 열려요"를 띄우고, 미리 만든 해설로 안내한다.
  - 이때는 사용자 주간 횟수를 차감하지 않는다.
- **익명 몫 상한**: 하루 예산은 모두가 같이 쓰므로, 익명 요청 합계는 하루 예산의 일부(시작값 30%)까지만 쓰게 한다. 익명 계정을 여러 개 만드는 남용이 가입자까지 막지 않게 하기 위해서다.
- **운영자 알림**: 예산의 50%, 80%, 100%에 닿으면 운영자에게 알린다(메일 또는 메신저 웹훅).
- **전체 스위치**: 서버 설정 하나로 실시간 AI 전체를 끄거나, 무료 횟수·모델을 바꾼다. 앱 업데이트가 필요 없다.
- **Anthropic 쪽 상한**: 콘솔의 월 지출 한도도 함께 걸어 둔다. 우리 코드에 버그가 있어도 여기서 멈춘다.
- 예산 금액은 3단계(비용 계산)에서 정한다.

## 4. 실시간 AI 대화 규칙

### 4.1 무엇을 1회로 세나

- **사용자가 보낸 질문 1개 = 1회.** 대화를 새로 여는 것과 이어서 묻는 것을 똑같이 센다. 추천 질문 버튼(지금 코치의 기본 질문, 후속 질문 칩)도 누를 때마다 1회다.
- **코치 화면을 열기만 해서는 세지 않는다.** 지금 코치는 대화가 없는 스팟을 열면 기본 질문을 자동으로 보낸다(`CoachSheet.tsx`). 실시간 AI를 열기 전에 이것을 바꾼다: 그 스팟의 미리 만든 해설이 있으면 먼저 보여 주고, 사용자가 질문을 보내거나 버튼을 누를 때만 실시간 AI를 부른다(9장).
- **차감 방식**: 질문이 서버에 들어오면 서버가 먼저 1회를 원자적으로 잡는다(확인과 증가를 한 번에). 그래서 동시에 여러 요청을 보내도 한도를 넘지 않는다.
- **되돌리는 경우**: 업스트림이 첫 응답 토큰을 보내기 전에 실패한 경우(서버 오류, 네트워크, 예산 마감), 그리고 거절(`stop_reason: refusal`)로 끝난 응답. 되돌릴 때는 차감할 때 쓴 주 키를 그대로 쓴다. 월요일 0시를 넘겨 끝난 요청이 새 주 횟수를 줄이지 않게 하기 위해서다.
- **되돌리지 않는 경우**: 응답이 시작된 뒤 사용자가 중단하거나 연결이 끊기면 1회로 센다. 스트리밍으로 이미 답을 받았기 때문이다. 대신 앱은 그때까지 받은 답을 대화에 남긴다(지금은 지운다).
- 서버는 앱 연결이 끊겨도 업스트림 응답을 끝까지 읽어 실제 사용량을 하루 전체 예산에 더한다. 중간에 끊어 버리면 마지막에 오는 사용량 정보를 못 받아 예산이 적게 계산된다.
- **자동 재시도 막기**: 지금 앱은 Anthropic SDK로 요청을 보내는데, SDK는 429·5xx를 기본 2번까지 다시 보낸다. 한도 소진이나 예산 마감 응답에는 서버가 `x-should-retry: false`를 붙이고, 코치 요청은 `maxRetries: 0`으로 보낸다. 한 번 누른 질문이 여러 번 차감되지 않게 하기 위해서다.
- 미리 만든 해설을 보는 것은 세지 않는다.

### 4.2 주간 한도

| | 주간 한도 (시작값) | 메모 |
|---|---|---|
| 익명 (19세 확인 후) | **주 10회 (제안, 확인 필요)** | 앱을 지우고 다시 깔면 새 익명 계정이 생겨 횟수를 또 받는다. 그래서 익명 몫은 작게 둔다 |
| 가입자 | **주 30회** | 결정됨 |

- **주의 기준**: KST 월요일 0시에 초기화한다. 주 키는 그 주 월요일의 KST 날짜로 한다(예: `2026-11-02`). ISO 주 번호(`2026-W45`)는 연말에 연도가 달력과 어긋나서 쓰지 않는다. 남은 횟수와 다음 초기화 시각을 AI 입력창 위에 항상 보여 준다.
- **주간이라 생기는 문제**: 한 사람이 30회를 하루에 다 쓸 수 있고, 주말에 사용이 몰릴 수 있다. 사용자별 하루 상한은 두지 않고 3장의 하루 전체 예산으로 막는다. 몰림이 실제로 보이면 그때 "하루 최대 15회" 같은 상한을 추가한다.
- **다 쓰면**: "이번 주 AI 질문을 다 썼어요. 월요일 0시에 다시 채워져요"를 띄운다. 그 스팟의 미리 만든 해설이 있으면 바로 보여 준다. 익명 사용자에게는 "가입하면 주 30회"를 함께 안내한다(가입할 이유).
- **이월 없음**: 남은 횟수는 다음 주로 넘어가지 않는다.
- **계정이 바뀔 때**: 익명 계정을 가입자로 승격하면 같은 계정이라 이번 주 사용 횟수가 그대로 이어진다. 익명 계정을 이미 있는 가입자 계정에 합치면, 익명 계정의 이번 주 사용 횟수를 가입자 계정에 더한다.

### 4.3 한 번의 질문에 거는 제한

비용은 횟수보다 **길이**에 더 크게 달려 있다. 그래서 횟수와 별도로 서버가 길이를 자른다(server-design 7.3).

| 항목 | 시작값 | 이유 |
|---|---|---|
| 질문 길이 | 1,000자 | 긴 붙여넣기 방지 |
| 스팟 정보 (`spotDetail`) | 2,000자 (`LIMITS.maxDetailLength`와 같게) | 앱이 만든 값이라 서버가 믿을 수 없다 |
| 해설 노트 (`userNotes`) | 시작값 1,000자 | 매 요청 시스템 프롬프트에 들어간다. 지금은 길이 제한이 없다 |
| 이전 AI 답변 한 턴 | 응답 길이 상한만큼 | 대화 내역은 서버가 저장하지 않고 앱이 보내므로 꾸밀 수 있다. 가짜 답변으로 주제 제한을 피하는 것도 막는다 |
| 요청 전체 입력 | 이전 대화 포함 시작값 20,000자 | 넘으면 거절한다. 질문 1회의 최대 비용을 이 값이 정한다 |
| 대화 길이 | 한 대화 10턴. 넘으면 새 대화로 | 이전 대화 전체가 매번 다시 전송되기 때문이다(data-inventory 5.1) |
| 응답 길이 (`max_tokens`) | 무료는 짧게 (3단계에서 정함) | 지금 앱 코드(`client.ts`)에 64,000으로 고정돼 있다. 무료에는 그대로 쓰지 않는다 |
| 모델 | 무료는 더 싼 모델 (Haiku 5.5 또는 Sonnet 5.5, 3단계에서 정함) | 지금 기본값은 Opus 5.5다 |
| 해설 깊이 (effort) | 무료는 고정 | 사용자가 높이면 비용이 커진다 |
| 프롬프트 캐싱 | 항상 켬 | 해설집 블록은 모든 사용자에게 같아서 사용자 사이에서도 캐시가 적중한다 |

### 4.4 남용 막기

- **익명 계정 만들기**: 익명 계정은 실시간 AI를 처음 쓸 때 만든다(data-inventory 7장). 앱이 Supabase 익명 로그인으로 직접 만들기 때문에 우리 `/api/v1` 서버를 지나지 않는다. 그래서 생성 빈도 제한은 Supabase Auth 설정(IP당 익명 로그인 한도)과 CAPTCHA(예: Turnstile)로 건다.
- **웹(PWA)의 한계**: 시크릿 창이나 사이트 데이터 삭제만으로 새 익명 계정이 생긴다. 기기 id도 새로 생기므로 "같은 기기" 제한은 스토어 앱에서 App Attest(iOS)·Play Integrity(Android)가 붙은 뒤에만 쓸 수 있다. 그래서 코치 서버는 익명 요청을 **계정과 함께 IP 기준으로도** 센다(시작값 IP당 주 20회).
- **익명 몫은 작게**(4.2)와 **익명 예산 상한**(3장)이 마지막 방어선이다.
- **가입자 계정 남용**: 이메일 인증코드 가입은 주소만 있으면 되므로, 같은 IP에서 새 가입자 계정을 만드는 빈도를 제한한다. Gmail처럼 `+` 별칭을 쓰는 주소는 `+` 뒤를 뗀 주소로 중복을 확인한다.
- **주제 제한**: 서버가 시스템 프롬프트를 소유하고, 홀덤 공부 밖의 요청은 거절하게 한다. 지금처럼 앱이 프롬프트 전체를 보내는 범용 중계는 실시간 AI를 열기 전에 없앤다(server-design 7.3). 4.3의 길이 제한이 함께 걸려야 한다.

## 5. 기록 동기화 규칙

- **가입자만** 쓴다. 익명 사용자는 내보내기/가져오기로 옮긴다.
- **가입자만**은 서버가 강제한다: 익명 세션(Supabase `is_anonymous`)의 동기화 요청은 403으로 거절한다(9장). 익명 계정은 AI 때문에 쉽게 만들어지므로, 막지 않으면 익명 계정마다 기록이 쌓여 DB 비용이 남용에 비례해 늘어난다.
- **서버 보관 상한 (시작값)**: 사용자당 **최근 1년, 최대 5,000건**. 기기 상한과 같게 둔다. 기기보다 많이 보관해도 무료 버전에는 그 기록을 보여 줄 화면이 없기 때문이다. 넘치면 서버에서만 오래된 것부터 정리한다. 기기 안 기록은 그대로 남는다.
- **지운 기록이 다시 올라오지 않게**: 서버는 보관 기간(1년)보다 오래된 `at`의 기록을 push에서 저장하지 않고 `duplicates`로 돌려준다. `rejected`로 돌려주면 기기에 거절 표시가 남고, 그냥 받으면 지운 기록이 새 순번으로 다시 저장돼 다른 기기로 내려간다.
- **기기 상한과의 관계**: 기기는 지금 5,000건까지 보관한다(`LIMITS.localAttemptCap`). 나중에 기기 저장소를 IndexedDB로 옮기면서 기기 상한을 올리면 서버 상한도 함께 올린다.
- **용량 줄이기**: 서버에 `detail`을 다 올릴지는 3단계에서 정한다. 빼면 다른 기기에서 그 문제의 카드·보드를 다시 볼 수 없다(data-inventory 10장).
- 동기화는 기본으로 켜고, 설정에서 끌 수 있게 한다. 끈 동안의 기록은 기기에만 쌓이고, 다시 켜면 그동안의 기록도 함께 올라간다(기기 상한 5,000건 안에서).

## 6. 서버 설정으로 바꿀 수 있어야 하는 값

실시간 AI를 열기 전에, 아래 값을 코드가 아니라 서버 설정(DB의 설정 행 또는 환경 변수)에서 읽게 만든다.

| 값 | 시작값 |
|---|---|
| 실시간 AI 전체 켜기/끄기 | 켜기 |
| 익명 주간 한도 | 10 (제안) |
| 가입자 주간 한도 | 30 |
| 하루 전체 AI 예산 | 3단계에서 정함 |
| 무료 모델, `max_tokens`, effort | 3단계에서 정함 |
| 질문 길이, 대화 턴 수 | 1,000자, 10턴 |
| 스팟 정보, 해설 노트, 요청 전체 입력 길이 | 2,000자, 1,000자, 20,000자 |
| 익명 몫 하루 예산 비율 | 30% |
| 익명 IP당 주간 한도 | 20 |
| 서버 기록 보관 상한 | 1년, 5,000건 |

## 7. "무료"를 표시하지 않을 때의 원칙

결정: 지금은 앱과 스토어에 "무료"나 "유료"를 말하지 않는다. 나중에 Pro를 만들 때 반발을 줄이려고 다음을 지킨다.

- 앱 설명, 공지, 스토어 문구에 "평생 무료", "무제한 무료" 같은 약속을 쓰지 않는다.
- 이용약관에 "서비스 내용과 이용 조건은 바뀔 수 있고, 바꿀 때는 미리 공지한다"는 조항을 둔다. 공지 기간은 약관을 쓸 때 법무 확인한다.
- 횟수 화면에는 "이번 주 남은 AI 질문 N회"처럼 사실만 적는다. "무료 N회"라고 쓰지 않는다.
- 나중에 기능을 유료로 옮길 때는, 이미 쓰던 사람에게 일정 기간을 그대로 주는 방식(유예)을 먼저 검토한다.

## 8. 광고를 나중에 검토할 때 바뀌는 것

지금은 광고 SDK를 넣지 않는다. 넣기로 하면 다음이 함께 바뀐다.

- **개인정보**: 광고 업체가 위탁·국외 이전 표(data-inventory 6장)에 들어가고, 광고 식별자가 수집 항목이 된다. iOS는 추적 허용 요청(ATT) 화면이 필요하다.
- **광고 내용**: 포커 앱이라 도박·카지노 광고가 붙기 쉽다. 광고 네트워크에서 도박, 사행성, 성인 카테고리를 막아야 하고, 그래도 사행성 이미지 위험이 남는다.
- **화면**: 공부 흐름(문제 → 결과 → 해설)을 끊지 않는 곳에만 둔다. 예: 하루 공부를 마친 뒤 화면.
- 대안: 광고를 보면 AI 질문 1회를 더 주는 "보상형 광고". AI 비용 일부를 광고로 메우는 구조라 검토 가치가 있다.

## 10. 무료 버전에 넣지 않는 것

Pro를 기획할 때 후보로 볼 것들이다. **약속이 아니다.** 앱이나 문서 밖에 적지 않는다.

- 더 많은 실시간 AI 질문, 더 좋은 모델
- 서버 기록 무제한 보관
- 고급 솔버 콘텐츠 팩 (멀티웨이, 펍 필드 착취 전략)
- 약점 리포트 심화
- (여러 기기 사이 기록 동기화는 무료 버전에 이미 들어 있어서 후보가 아니다. 5장)

## 11. 남은 결정

- **익명 주간 한도**: 제안은 주 10회. 확인 필요.
- **새로 제안한 시작값**(리뷰 반영, 확인 필요): 익명 몫 하루 예산 30%, 익명 IP당 주 20회, 요청 전체 입력 20,000자, 해설 노트 1,000자, 서버 기록 상한 5,000건(1만 건에서 내림).
- **3단계 비용 계산**: 무료 모델, `max_tokens`, 하루 전체 AI 예산 금액, 서버 기록에 `detail`을 올릴지.
