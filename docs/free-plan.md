# PubAZ 무료 버전 기획

> 상태: **설계 2단계 (무료 버전)**, 2026-11-06. Pro(유료)는 아직 기획하지 않는다. 결제도 붙이지 않는다.
> 앞 단계: [`data-inventory.md`](data-inventory.md) (회원 시스템과 데이터 구분). 서버 구조: [`server-design.md`](server-design.md).
> 숫자(횟수, 상한)는 **시작값**이다. 앱 업데이트 없이 서버 설정으로 바꿀 수 있게 만든다(6장).

## 1. 2단계 결정 기록

| 항목 | 결정 | 메모 |
|---|---|---|
| 범위 | **무료 버전만 먼저 기획**한다 | 결제·환불·영수증 보존 의무가 뒤로 밀린다. 사용 데이터를 보고 Pro를 정한다 |
| 실시간 AI 대화 횟수 | **주간 묶음** | 가입자 시작값 주 30회. 익명 사용자 몫은 4장 |
| 무료 표시 | **아직 표시하지 않음** | "무료"나 "유료" 얘기를 앱·스토어에 하지 않는다. 나중을 위한 문구 원칙은 7장 |
| 광고 | **나중에 검토** | 지금은 광고 SDK를 넣지 않는다. 넣게 되면 바뀌는 것은 8장 |
| 기록 동기화 | **가입자에게 무료** | 서버 보관 상한을 둔다(5장) |

## 2. 무료 버전 구성

비용이 드는 것은 **실시간 AI 대화**와 **기록 동기화(DB)** 둘뿐이다. 나머지는 전부 기기에서 돌아 사용자가 늘어도 우리 비용이 거의 0이다.

| 기능 | 익명 | 가입자 | 우리 비용 | 메모 |
|---|---|---|---|---|
| 퀴즈 (프리플랍, 레인지 암기, 팟 오즈·EV, 에퀴티) | 무제한 | 무제한 | 0 | 기기에서 계산 |
| 차트, 계산기, 핸드 플레이 | 무제한 | 무제한 | 0 | 기기에서 계산 |
| 기록 화면 | 무제한 (이 기기 기록) | 무제한 (동기화된 기록) | 0 | |
| 오늘의 문제 (매일 5문제) | 됨 | 됨 | 0 | 문제 풀은 정적 파일, 고르는 건 기기에서 (server-design 10장) |
| 미리 만든 AI 해설 | 무제한 | 무제한 | 스팟당 한 번 만들 때만 | 나이 확인 없이 누구나 (data-inventory D) |
| 솔버 콘텐츠 팩 | 됨 | 됨 | 파일 전송량만 | 아직 없음. 범위는 만들 때 정한다 |
| **실시간 AI 대화** | 19세 확인 후 주간 한도 | 주 30회 | **질문마다** | 4장 |
| **기록 동기화** | 안 됨 (내보내기/가져오기만) | 됨 | **DB 용량** | 5장 |
| 내 API 키로 AI 쓰기 | 됨 (고급 설정) | 됨 (고급 설정) | 0 | 횟수 제한 없음. 사용자가 자기 키 비용을 낸다. 일반 사용자에게는 숨긴다 |

## 3. 비용 안전장치 (혼자 운영할 때 필수)

사용자별 한도와 별개로, 전체에 거는 상한이다. 요금 폭탄을 막는 마지막 장치라서 실시간 AI를 여는 날부터 켜 둔다.

- **하루 전체 AI 예산**: 서버가 응답마다 실제 토큰 사용량으로 비용을 더한다. 그날(KST) 합계가 정한 금액을 넘으면 실시간 AI를 모두에게 닫는다.
  - 닫혀 있는 동안 앱에는 "오늘 AI 해설은 마감됐어요. 내일 0시에 다시 열려요"를 띄우고, 미리 만든 해설로 안내한다.
  - 이때는 사용자 주간 횟수를 차감하지 않는다.
- **운영자 알림**: 예산의 50%, 80%, 100%에 닿으면 운영자에게 알린다(메일 또는 메신저 웹훅).
- **전체 스위치**: 서버 설정 하나로 실시간 AI 전체를 끄거나, 무료 횟수·모델을 바꾼다. 앱 업데이트가 필요 없다.
- **Anthropic 쪽 상한**: 콘솔의 월 지출 한도도 함께 걸어 둔다. 우리 코드에 버그가 있어도 여기서 멈춘다.
- 예산 금액은 3단계(비용 계산)에서 정한다.

## 4. 실시간 AI 대화 규칙

### 4.1 무엇을 1회로 세나

- **사용자가 보낸 질문 1개 = 1회.** 대화를 새로 여는 것과 이어서 묻는 것을 똑같이 센다.
- **AI 응답이 성공했을 때만 차감한다.** 서버 오류, 네트워크 끊김, 예산 마감으로 답을 못 받으면 차감하지 않는다(server-design 7.2의 "되돌리기").
- 미리 만든 해설을 보는 것은 세지 않는다.

### 4.2 주간 한도

| | 주간 한도 (시작값) | 메모 |
|---|---|---|
| 익명 (19세 확인 후) | **주 10회 (제안, 확인 필요)** | 앱을 지우고 다시 깔면 새 익명 계정이 생겨 횟수를 또 받는다. 그래서 익명 몫은 작게 둔다 |
| 가입자 | **주 30회** | 결정됨 |

- **주의 기준**: KST 월요일 0시에 초기화한다. 남은 횟수와 다음 초기화 시각을 AI 입력창 위에 항상 보여 준다.
- **주간이라 생기는 문제**: 한 사람이 30회를 하루에 다 쓸 수 있고, 주말에 사용이 몰릴 수 있다. 사용자별 하루 상한은 두지 않고 3장의 하루 전체 예산으로 막는다. 몰림이 실제로 보이면 그때 "하루 최대 15회" 같은 상한을 추가한다.
- **다 쓰면**: "이번 주 AI 질문을 다 썼어요. 월요일 0시에 다시 채워져요"를 띄운다. 그 스팟의 미리 만든 해설이 있으면 바로 보여 준다. 익명 사용자에게는 "가입하면 주 30회"를 함께 안내한다(가입할 이유).
- **이월 없음**: 남은 횟수는 다음 주로 넘어가지 않는다.

### 4.3 한 번의 질문에 거는 제한

비용은 횟수보다 **길이**에 더 크게 달려 있다. 그래서 횟수와 별도로 서버가 길이를 자른다(server-design 7.3).

| 항목 | 시작값 | 이유 |
|---|---|---|
| 질문 길이 | 1,000자 | 긴 붙여넣기 방지 |
| 대화 길이 | 한 대화 10턴. 넘으면 새 대화로 | 이전 대화 전체가 매번 다시 전송되기 때문이다(data-inventory 5.1) |
| 응답 길이 (`max_tokens`) | 무료는 짧게 (3단계에서 정함) | 지금 앱 설정은 64,000이다. 무료에는 그대로 쓰지 않는다 |
| 모델 | 무료는 더 싼 모델 (Haiku 5.5 또는 Sonnet 5.5, 3단계에서 정함) | 지금 기본값은 Opus 5.5다 |
| 해설 깊이 (effort) | 무료는 고정 | 사용자가 높이면 비용이 커진다 |
| 프롬프트 캐싱 | 항상 켬 | 해설집 블록은 모든 사용자에게 같아서 사용자 사이에서도 캐시가 적중한다 |

### 4.4 남용 막기

- 익명 계정은 실시간 AI를 처음 쓸 때 만든다(data-inventory 7장). 재설치로 계정을 새로 만드는 비용을 높이기 위해 익명 몫을 작게 둔다(4.2).
- 서버에서 같은 IP·같은 기기의 익명 계정 생성 빈도를 제한한다(예: IP당 하루 몇 개).
- 스토어 앱이 되면 App Attest(iOS)·Play Integrity(Android)로 진짜 앱에서 온 요청인지 확인한다(server-design 12장).
- 주제 제한: 서버가 시스템 프롬프트를 소유하고, 홀덤 공부 밖의 요청은 거절하게 한다. 지금처럼 앱이 프롬프트 전체를 보내는 범용 중계는 실시간 AI를 열기 전에 없앤다(server-design 7.3).

## 5. 기록 동기화 규칙

- **가입자만** 쓴다. 익명 사용자는 내보내기/가져오기로 옮긴다.
- **서버 보관 상한 (시작값)**: 사용자당 **최근 1년, 최대 1만 건**. 넘치면 서버에서만 오래된 것부터 정리한다. 기기 안 기록은 그대로 남는다.
- **기기 상한과의 관계**: 기기는 지금 5,000건까지 보관한다(`LIMITS.localAttemptCap`). 새 기기에서 받아오면 최근 5,000건만 남는다. 기록이 많은 사용자를 위해 나중에 기기 저장소를 IndexedDB로 옮기면서 기기 상한을 올릴지 검토한다.
- **용량 줄이기**: 서버에 `detail`을 다 올릴지는 3단계에서 정한다. 빼면 다른 기기에서 그 문제의 카드·보드를 다시 볼 수 없다(data-inventory 10장).
- 동기화는 기본으로 켜고, 설정에서 끌 수 있게 한다. 끄면 그 뒤 기록은 서버로 가지 않는다.

## 6. 서버 설정으로 바꿀 수 있어야 하는 값

실시간 AI를 열기 전에, 아래 값을 코드가 아니라 서버 설정(DB의 설정 행 또는 환경 변수)에서 읽게 만든다.

| 값 | 시작값 |
|---|---|
| 실시간 AI 전체 켜기/끄기 | 켜기 |
| 익명 주간 한도 | 10 (제안) |
| 가입자 주간 한도 | 30 |
| 하루 전체 AI 예산 | 3단계에서 정함 |
| 무료 모델, `max_tokens`, effort | 3단계에서 정함 |
| 질문 길이, 대화 턴 수 | 1,000자, 10턴 |
| 서버 기록 보관 상한 | 1년, 1만 건 |

## 7. "무료"를 표시하지 않을 때의 원칙

결정: 지금은 앱과 스토어에 "무료"나 "유료"를 말하지 않는다. 나중에 Pro를 만들 때 반발을 줄이려고 다음을 지킨다.

- 앱 설명, 공지, 스토어 문구에 "평생 무료", "무제한 무료" 같은 약속을 쓰지 않는다.
- 이용약관에 "서비스 내용과 이용 조건은 바뀔 수 있고, 바꿀 때는 미리 공지한다"는 조항을 둔다. 공지 기간은 약관을 쓸 때 법무 확인한다.
- 횟수 화면에는 "이번 주 남은 AI 질문 N회"처럼 사실만 적는다. "무료 N회"라고 쓰지 않는다.
- 나중에 기능을 유료로 옮길 때는, 이미 쓰던 사람에게 일정 기간을 그대로 주는 방식(유예)을 먼저 검토한다.

## 8. 광고를 나중에 검토할 때 바뀌는 것

지금은 광고 SDK를 넣지 않는다. 넣기로 하면 다음이 함께 바뀐다.

- **개인정보**: 광고 업체가 위탁·국외 이전 표(data-inventory 6장)에 들어가고, 광고 식별자가 수집 항목이 된다. iOS는 추적 허용 요청(ATT) 화면이 필요하다.
- **광고 내용**: 포커 앱이라 도박·카지노 광고가 붙기 쉽다. 광고 네트워크에서 도박, 사행성, 성인 카테고리를 막아야 하고, 그래도 사행성 이미지 위험이 남는다.
- **화면**: 공부 흐름(문제 → 결과 → 해설)을 끊지 않는 곳에만 둔다. 예: 하루 공부를 마친 뒤 화면.
- 대안: 광고를 보면 AI 질문 1회를 더 주는 "보상형 광고". AI 비용 일부를 광고로 메우는 구조라 검토 가치가 있다.

## 9. 코드에 반영할 것 (서버를 실제로 연결할 때)

| 위치 | 지금 | 바꿀 것 |
|---|---|---|
| `server/quota.ts` | 하루 기준(`kstDateKey`, 무료 하루 5회, Pro 100회) | 주간 기준(KST 월요일 시작 주 키, 예: `2026-W45`), 익명·가입자 한도, 서버 설정에서 읽기 |
| `shared/contracts.ts` `MeResponse.coach` | `used`, `limit`, `resetsAt` | 그대로 쓴다. `resetsAt`이 다음 월요일 0시(KST)가 된다. 익명/가입자 구분 필드 추가 검토 |
| `usage_counters` 보관 | 최근 40일 (data-inventory A) | 주간 키 기준으로 최근 6주 |
| 하루 전체 AI 예산 | 없음 | 새 표 `ai_spend(day, cost)`와 응답마다 더하는 코드 |
| `api/anthropic.ts` 범용 중계 | 앱이 프롬프트 전체를 보냄 | `/api/v1/coach/messages`로 옮기고 서버가 프롬프트·모델·길이를 정함 (server-design 7.3) |
| `src/state/settings.ts` 기본 모델 | Opus 5.5, `max_tokens` 64,000 | 서버 경유 모드에서는 서버가 정한 값을 쓴다 |

## 10. 무료 버전에 넣지 않는 것

Pro를 기획할 때 후보로 볼 것들이다. **약속이 아니다.** 앱이나 문서 밖에 적지 않는다.

- 더 많은 실시간 AI 질문, 더 좋은 모델
- 서버 기록 무제한 보관
- 고급 솔버 콘텐츠 팩 (멀티웨이, 펍 필드 착취 전략)
- 약점 리포트 심화, 기기 여러 대 동시 사용

## 11. 남은 결정

- **익명 주간 한도**: 제안은 주 10회. 확인 필요.
- **3단계 비용 계산**: 무료 모델, `max_tokens`, 하루 전체 AI 예산 금액, 서버 기록에 `detail`을 올릴지.
- 1단계에서 남은 것: 나이 확인 방법, Supabase·Vercel 리전.
